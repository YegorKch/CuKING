# Apps Script — API «CuKING»

## Установка

1. Загрузить `CuKING_база.xlsx` на Google Диск → открыть → **Файл → Сохранить как Google Таблицы**.
   Дальше работать с этой Google-таблицей, xlsx больше не нужен.
2. В таблице: **Расширения → Apps Script**.
3. Заменить содержимое `Код.gs` содержимым [Code.gs](Code.gs).
4. **Настройки проекта** (шестерёнка слева) → включить «Показывать файл манифеста appsscript.json» →
   открыть `appsscript.json` в редакторе и заменить содержимым [appsscript.json](appsscript.json).
5. Проверить часовой пояс таблицы: **Файл → Настройки → Часовой пояс** — `(GMT+05:00) Алматы`.
   Он должен совпадать с `timeZone` в манифесте, иначе даты будут съезжать на день.
6. В редакторе выбрать функцию `debugSnapshot` → **Выполнить** → выдать доступ
   («Дополнительные настройки → Перейти на страницу…» — это нормально для своего скрипта).
   В журнале: число блюд, колоды, блюда без шагов или ингредиентов (если есть).
7. Выбрать `debugWriteCycle` → **Выполнить**. В журнале: запись, `duplicate: true`, «Тестовая строка удалена: true».
8. **Начать развёртывание → Новое развёртывание** → тип «Веб-приложение»:
   - Запуск от имени: **Я**
   - У кого есть доступ: **Все**
9. Скопировать URL вида `https://script.google.com/macros/s/…/exec` — его вводим в приложении
   при первом запуске. В репозиторий URL не кладём.

## Обновление кода

После правок: **Начать развёртывание → Управление развёртываниями → ✏️ → Версия: новая версия**.
Так URL остаётся прежним. «Новое развёртывание» создаёт новый URL — телефоны придётся перенастраивать.

Правки рецептов в таблице переразвёртывания **не требуют** — приложение подтянет их при следующем открытии.

## Протокол

`GET <url>` → вся база:

```json
{
  "ok": true,
  "dishes": [{ "id": "pork-cream", "name": "Свинина в сливочном соусе", "desc": "…", "cat": "Горячее",
               "garnish": true, "time": 35, "portions": 4, "tech": ["плита"], "diff": 1,
               "tags": ["мясное"], "active": true }],
  "ingredients": { "pork-cream": [{ "p": "Сливки 20%", "q": 250, "u": "мл", "req": true }] },
  "steps": { "pork-cream": [{ "n": 1, "title": "Нарезка", "text": "…", "tech": "" }] },
  "history": [{ "id": "…", "date": "2026-09-29", "dish": "pork-cream", "garnish": "g-rice",
                "type": "готовили", "re": 5, "ra": 4 }],
  "decks": [{ "name": "Основное", "cats": ["Суп", "Горячее"] }, { "name": "Гарниры", "cats": ["Гарнир"] }],
  "serverTime": "2026-09-29T04:00:00.000Z"
}
```

`garnish` у блюда: `true` — нужен гарнир, `false` — самодостаточное, `null` — не горячее.
`q: null` — «по вкусу» / «щепотка». Пустая оценка — `""`.

`POST <url>`, тело — JSON строкой с `Content-Type: text/plain` (чтобы браузер не делал CORS-preflight):

| action | Поля | Что делает |
|---|---|---|
| `log` | `entry: { id, date: "ГГГГ-ММ-ДД", dish, garnish, type: "готовили" \| "пауза", re, ra }` | `appendRow` в «Историю». Если `id` уже есть — ничего не пишет, `result.duplicate = true` |

Ответ на POST — то же, что GET, плюс `result`. Ошибка — `{ "ok": false, "error": "текст" }`.

Запись идёт под `LockService`, существующие строки не меняются — одновременная работа
с двух телефонов ничего не портит.

## Что можно менять в таблице руками

- Любые рецепты, ингредиенты, шаги. Новое блюдо — новая строка в «Блюдах» с уникальным `ID`
  и строки с этим `ID` в «Ингредиентах» и «Шагах».
- `Активно = НЕТ` — убрать блюдо из рандомайзера, не удаляя.
- Новая колода (например, «Салаты») — строка в «Справочниках»: `Колода = Салаты`, `Категории_колоды = Салат`,
  и блюда с категорией «Салат». Приложение само покажет новую колоду.
- «Историю» руками лучше не трогать: из неё считаются оценки, паузы и антиповтор.
